# STELE security audit against the threat model (November 2026)

Scope: `main` at `b03e5dd` (Python source, `RESTORE.ps1` template, build files, git history).
Method: manual source review of every module, plus small proof-of-concept scripts run against the real functions on Linux (Python 3.13, no PySide6, no Windows). Nothing here was run on Windows, against IMAPI, or against the shipped buyer ZIP.

The attack-vector IDs (NET, FS, MOD, AI, LIC, RES, SUP) and P0 items come from the "STELE Studio architecture and threat model" spec. This document maps them to the code that exists today. No application code was changed.

Baseline: `pytest` gives 87 passed, 7 skipped, 5 failed. All 5 failures are a missing `PySide6` or the Windows-only volume lookup in this Linux container, not test regressions.

What already holds up well, so these don't get re-litigated:

- **No model code is ever executed.** No `pickle`, `torch.load`, `trust_remote_code`, `eval`/`exec`, `shell=True`, `os.system`, archive extraction, or installer launch anywhere in `stele/`. The only parser for model bytes is `safetensors_dtype` (`stele/docs/spec.py`), which caps the header at 8 MB and uses `json.loads`. GGUF is identified by file name only. **P0-1 passes**, with the F3 caveat that the *PDF renderer* treats repo text as markup.
- **Revision pinning for HF.** `enqueue_model` refuses a job with no commit SHA, and the worker downloads by `commit_sha` (`stele/download/queue.py:49`, `worker.py:562`). NET-02 is mitigated for HF.
- **TLS.** httpx and `huggingface_hub` default to certificate verification, and nothing sets `verify=False` (NET-05).
- **SQL.** Every query is parameterised. The one f-string in `search_catalog` only joins fixed clause strings (`db.py:579`).
- **Licensing secrets.** No signing secret is in the current source or exe. The Gumroad product ID is public. A grep test guards against `_OFFLINE_SECRET` returning (P0-4 passes for source; see F16 for history).
- **Subprocess.** `par2` runs with an argument list, `shell=False`, and fixed flags (`stele/burn/par2.py:76`). No file names reach a shell (FS-17 OK apart from F11).
- **Civitai key** is only sent to `*.civitai.com` in `resolve_download`, and `stream_range` refuses non-civitai redirects when the key is attached.
- **Build-time par2** is pinned by SHA-256 for the ZIP, the exe and the license (`tools/fetch_par2.py`).
- **Log redaction** filter for HF tokens, `Authorization:` and `?token=`, and httpx/hub loggers held at WARNING.

## 3. Findings in detail

### F1. Path traversal through remote file names (High)

**Flow:** `stele/hub/civitai.py:140` `to_details` normalises `name` with `.replace("\\", "/").strip("/")`. That removes leading and trailing slashes but keeps `..` and drive prefixes. Then `Queue.enqueue_model` (`stele/download/queue.py:98`) builds `local = staging / relative_path`, and `DownloadWorker._one_file` (`worker.py:502`) does `mkdir` and writes there. `_finalize_model` (`queue.py:262`) then does `target = revision_dir / relative`, `target.unlink()` if it exists, and `shutil.move`. `purge_incomplete` (`queue.py:150`) deletes whatever `local_path` the DB holds.

**PoC (run against the real `to_details`):**
```
names → ['../../../AppData/Roaming/Microsoft/Windows/Start Menu/Programs/Startup/x.bat', 'C:/Windows/Temp/y.dll']
staging\7 / name → C:\Users\u\Stele\staging\7\..\..\..\AppData\Roaming\...\Startup\x.bat
staging\7 / 'C:/Windows/Temp/y.dll' → C:\Windows\Temp\y.dll   (pathlib drops the base)
```
If no SHA256 is published, the file is accepted as `done` (F5). If one is, the attacker publishes the matching hash. Result: arbitrary file write as the user. Writing to the Startup folder gives code execution at the next logon. The pre-existing-file `unlink()` in finalize also makes it an arbitrary overwrite or delete.

**Reachability:** needs Civitai (or an attacker on its API path) to return such a name. Civitai probably sanitises uploads, but Stele must not depend on that. HF names come from git trees, which reject `..` components. Backslashes, `:` (NTFS alternate data streams, FS-06), reserved device names (`CON`, `NUL`, FS-07), trailing dots and spaces, and case collisions (FS-08) are not checked for either source. The same names flow into `checksums.sha256` on the disc and into RESTORE.ps1 (F8).

**Fix:** one `safe_relative(name) -> PurePosixPath` used at the API boundary (`to_details`, `HubClient.details`) and again at every join (`enqueue_model`, `_finalize_model`, `collect_tree`). It should:
- reject empty, absolute, drive-qualified (`PureWindowsPath(name).drive or .root`), `..`, `.` components, `\`, `:`, control characters, trailing dot or space, Windows reserved names, and components over 255 characters
- NFC-normalise, then reject case-insensitive duplicates within a job
- after joining, check `os.path.realpath(target)` is inside `realpath(base)` with `os.path.commonpath`, not `startswith`, and refuse if any existing parent is a reparse point (`os.lstat(p).st_file_attributes & FILE_ATTRIBUTE_REPARSE_POINT`)
- in `_finalize_model`, never `unlink` an existing target outside the new revision dir. In `purge_incomplete`, delete only paths that pass the same containment check against the job's staging dir

**Regression tests (T-001):**
- `test_civitai_rejects_traversal_names` covers `../x`, `a/../../x`, `C:/x`, `C:x`, `x:stream`, `CON.txt`, `a\\..\\x`, and `x.` → `HubError`
- `test_enqueue_refuses_path_outside_staging` passes a `HubFile(path="../x")` straight to `enqueue_model` → `ValueError`
- `test_finalize_never_writes_outside_revision_dir` uses a crafted DB row
- `test_purge_incomplete_ignores_foreign_local_path`
- `test_case_collision_rejected` covers `Model.bin` and `model.bin` in one job

### F2. HF token forwarded off-origin, allowlist bypass (High)

**Flow:** `download_hub_file` (`worker.py:279`) builds `headers = build_hf_headers(token)` (which includes `authorization: Bearer hf_…`) and `location` from `get_hf_file_metadata`. For LFS and Xet files, that is the signed CDN URL. Lines 302–306 then **append whatever host `location` names to the allowlist**, so the allowlist never refuses anything HF metadata returns. `stream_range` (`worker.py:197–212`) sends the same `request_headers` to the first host and to every redirect hop.

**PoC (real `stream_range`, mocked transport):**
```
1 auth per hop: [('huggingface.co', 'Bearer hf_SECRET'), ('evil-cdn.example', 'Bearer hf_SECRET')]
```
Today the token goes to `cdn-lfs*.huggingface.co`, `cas-bridge.xethub.hf.co`, and any third-party storage HF redirects to. If HF metadata is spoofed or compromised, or a CDN hop redirects to a host in the allowlist, the token goes there too.

**Fix:**
- send `Authorization` only when the request host is exactly `huggingface.co` (or `hf.co`). Pre-signed CDN URLs do not need it
- in `stream_range`, drop `Authorization` and `Cookie` whenever a hop changes origin (scheme, host, port). That is what browsers and `requests` do
- delete the `allow.append(host)` branch and fail closed with `kind="source"`. If HF adds a CDN, update the list deliberately
- keep `https` only, and refuse IP-literal hosts, `localhost`, and hosts that resolve to private or loopback ranges (NET-04, NET-15)

**Regression tests (T-010):**
- `test_auth_not_sent_to_cdn`
- `test_auth_dropped_on_cross_origin_redirect`
- `test_unknown_location_host_rejected`
- `test_redirect_to_loopback_rejected`

### F3. ReportLab markup injection from repo content (High)

**Flow:** `write_spec_pdf` (`stele/docs/pdf.py:54, 58–68`) builds `Paragraph(f"{spec.license_name}. {spec.license_excerpt}")` and the architecture/quant lines with no escaping. `license_excerpt` is the first 500 characters of the repo's `LICENSE*` file (`queue.py:399`). `facts.architecture` comes from `config.json`. ReportLab 4/5 ships with `trustedSchemes = ['file','rml','data','https','http','ftp']` and `trustedHosts = None`. (`write_howto_pdf` does escape its text.)

**PoC (ReportLab 5.0.1, same call shape):**
- `MIT. <img src="/tmp/claude-0/secret.png" .../>` → the PDF contains an `/Subtype /Image` XObject read from that local file. With `http://…` it would fetch the URL during finalize, which is SSRF and a tracking beacon, and `http://127.0.0.1:11434/…` hits local services.
- `MIT <b>unclosed` → `ValueError: Parse error`. `_finalize_model` raises *after* it has already moved every file from staging into the vault, but before writing the catalog row. The job is marked failed and the vault holds an orphan revision (NET-13, FS-14). That interrupted finalize is also the state that leaves F1's write in place.

**Fix:**
- `xml.sax.saxutils.escape()` every interpolated value in `pdf.py` and `labels.py`, or render untrusted text as `Preformatted` or `XPreformatted`
- set `rl_config.trustedSchemes = []` (or `['data']`) at import, so no markup can read files or URLs
- make `_finalize_model` transactional: write the docs first, or catch doc failures and still record the catalog row with a "docs failed" note, so a bad card never leaves a half-finalized vault

**Regression tests (T-017):**
- `test_spec_pdf_escapes_license_markup` (`<img>`, `<a href>`, `<font color=...>`, unbalanced tags)
- `test_spec_pdf_never_reads_files_or_urls` (patch `open_for_read` to fail)
- `test_finalize_records_catalog_even_if_docs_fail`

### F4. Range resume and size bounds (Medium)

**Flow:** `stream_range` (`worker.py:228–257`) treats any 206 as a valid resume and appends from the start of the body. It never compares the `Content-Range` start to `existing`, or the total to `expected_size`. It writes until the server stops, and `expected_size` is only used for the free-space precheck. On 416 it renames `.partial` to `dest` with no size check. An existing `dest` with no `.partial` is trusted as-is (`worker.py:182`).

**PoC:**
```
2 wrote 50 bytes with expected_size=10
3 resumed file: b'PPPPPPPPPPXXXXXXXXXX'   (server said bytes 0-9/20, client appended at 10)
```
When a SHA-256 exists, the hash check catches the corruption afterwards. When none exists (F5), the corrupt file is accepted. An unbounded body can fill the staging disk (NET-07).

**Fix:**
- on 206, parse `Content-Range: bytes S-E/T`, require `S == existing` and `T == expected_size` (when known), else delete `.partial` and restart
- abort once `written > expected_size`
- on 416, accept only if `partial.stat().st_size == expected_size`
- check `dest` size against `expected_size` before trusting it
- record and compare the ETag across a resume (`If-Range`) (T-003)

**Regression tests:** `test_206_wrong_start_restarts`, `test_body_longer_than_expected_aborts`, `test_416_with_short_partial_restarts`, `test_existing_dest_wrong_size_redownloads`.

### F5. Integrity is fail-open (Medium)

`evaluate_hash` (`worker.py:82`) returns `"done"` when the expected value is missing or not 64 hex characters. `HubClient.details` sets `etag` only for LFS files (`hub/client.py:96`). So `config.json`, tokenizer files, `*.py`, `LICENSE`, and every small file are never checked against the source. HF does publish their git blob SHA-1 (`blob_id`). The same applies to Civitai files without `hashes.SHA256` and to the LM Studio pack (F13). The UI and catalog record these files the same as verified ones.

**Fix:**
- verify non-LFS HF files against the git blob SHA-1 (`sha1(b"blob %d\0" % size + data)`)
- add a per-file `integrity` field (`source-sha256`, `git-sha1`, `local-only`) to the DB and to `checksums.sha256` or the manifest, and show "unverified against source" in Library and the spec
- optionally block burning `local-only` executables

**Regression tests:** `test_missing_hash_is_marked_unverified`, `test_non_lfs_file_checked_against_git_blob_sha1`.

### F6. Burn re-hashes the vault instead of checking it (Medium)

`model_payload` → `collect_tree` (`burn/layout.py:37`) hashes each vault file *now* and writes that hash to the disc's `checksums.sha256` and `ARCHIVE_MANIFEST.json`. It never reads the vault's own `checksums.sha256` or `job_files.sha256`. A file changed in the vault (malware, a disk fault, a user edit) is burned and then "verified" against its own new hash. The evidence package does detect this (`provenance.py` `status == "changed"`), but only for Pro, and only as a warning.

**Fix:** before building a volume, compare each payload hash against the recorded download hash. On mismatch, stop with "vault item changed since download". Treat files with no record as F5 `local-only`. Also skip symlinks and reparse points in `collect_tree` (FS-03/04), since `rglob` + `is_file()` follows a file symlink and would copy an outside file onto the disc.

**Regression tests (T-012):** `test_burn_refuses_modified_vault_file`, `test_collect_tree_skips_symlinks`.

### F7. Sampled readback (Medium)

`verify_volume` (`burn/imapi.py:468`) fully hashes the volume only when it is 8 GiB or less. Above that, files of 64 MB or more are compared at three 64 MB windows against the staged tree. A BD-25 or larger disc with real weights is therefore never fully read back. The UI says "Sampled verify", so this is honest, but it does not meet §6.3 or acceptance criterion "Media".

**Fix:** offer a full-readback option on by default for Pro, and record `full` or `sampled` in the catalog's health. Hash on the read with the same streaming `hash_file`. For speed, only the read is needed, since the expected hashes are already known.

### F8. RESTORE.ps1 trusts disc metadata (Medium)

`stele/restore/restore_ps1.py`:
- Line 117–120: `$top = ($relative -split '/')[0]` lets `MODELS/../../../Users/x/AppData/...` through, and `Join-Path` does not normalise. Copy-Tolerant writes there with `FileMode::Create`, which overwrites (RES-01, RES-11).
- Lines 182–224: `split.path` and `part.path` from `VOLUME.json` are used with **no** folder check, then `Move-Item` and `Remove-Item -Force` (RES-03: a tampered `VOLUME.json` deletes or replaces arbitrary files).
- `$volume.label` is concatenated into a path (line 147).
- Existing files under `-Destination` whose hash differs are silently replaced (RES-10).
- `checksums.sha256` sits on the same disc, so any tampering beats it (RES-02). Only a signed manifest fixes that (P2).

On a disc Stele burned, these paths are the repo file names, so F1's names flow straight here. **Fix:**
- add a `Test-SafeRelative` that rejects `..`, `.`, `:`, `\`, leading `/`, and reserved names. Then `[IO.Path]::GetFullPath((Join-Path …))` must `StartsWith($Destination + $sep, OrdinalIgnoreCase)`. Apply it to every path from either file
- refuse to overwrite a non-matching existing file unless `-Overwrite` is passed
- keep every part until the joined file's hash matches. Today part 1 is moved to `.joining` and each later part is deleted inside the copy loop (template lines 206–213), before the hash check at line 218, so a failed join destroys the parts. Join into a separate file, verify it, and only then remove the parts
- validate `label` against `^STELE_[0-9a-f]{8}_\d+$`

**Regression tests (T-014):** a Pester or `pwsh` test in CI that runs the generated script against a crafted disc tree. Cases: `..` in `checksums.sha256`, `..` in `split_files.parts`, an existing file with a different hash. Add a Python test asserting the template contains the containment function.

### F9. Execution policy (Low/Medium)

`burn/layout.py:401`, `docs/howto.py:109` and `docs/labels.py:109` all print `powershell -ExecutionPolicy Bypass -File .\RESTORE.ps1`. §13.3 says not to. `-Scope Process` Bypass is common practice, so the real risk is that the script is unsigned and its integrity rests on the same disc (RES-02). **Fix:** Authenticode-sign `RESTORE.ps1` with the release cert, document `Unblock-File` / `-ExecutionPolicy RemoteSigned`, and ship `ARCHIVE_SPEC.txt` so recovery doesn't depend on running a script.

### F10. Pro entitlement is an unauthenticated DB value (Medium, business)

`is_activated` (`license.py:178`) is `db.get_setting('license_status') == 'Pro'`. Running `UPDATE settings SET value='Pro' WHERE key='license_status'` on `%LOCALAPPDATA%\Stele\stele.db` unlocks burn, span, PAR2 and evidence permanently. `revalidate` returns `"offline"` (no revoke) if the keyring entry is missing, so the edit is never re-checked. 5xx or unparseable replies also count as offline, so blocking `api.gumroad.com` keeps a refunded key active forever (LIC-07 by design, but unbounded).

**Fix (as the spec and `STELE_MASTER_LIST.md` B2 already say):** have a small server you control return an Ed25519-signed entitlement `{product, key_hash, machine_id, issued, not_after}`. Ship only the public key, store the blob in Credential Manager, verify it on each `require_pro`, and allow a bounded grace (for example 30–60 days) with clock-rollback detection (LIC-04). Gumroad alone cannot sign responses. Short of a server, at least treat a missing stored key as **not** Pro, and cap the offline window.

**Tests (T-020):** `test_db_flag_without_valid_entitlement_is_free`, `test_missing_keyring_key_is_free`, `test_offline_grace_expires`.

### F11. Executable search paths (Low)

- `find_par2` (`burn/par2.py:33`) prefers `settings.par2_path` from SQLite, then the bundle, then `shutil.which("par2")`. On Windows Python 3.12, that still searches the current directory first unless `NoDefaultCurrentDirectoryInExePath` is set. "A compromised local database must not redefine trusted executable paths" (§5.3).
- `imapi._create` (`burn/imapi.py:65`) points comtypes `gen_dir` at `%TEMP%\stele_comtypes_gen`. Generated `.py` modules are imported from there.
- `RESTORE.ps1` uses `Get-Command par2` from `PATH`.

Same-user attackers already own the account, so the impact is low, but these are easy to close. **Fix:** check the bundled `par2.exe` against `EXE_SHA256` at runtime, and accept a user path only after an explicit file picker with its hash shown. Put comtypes `gen_dir` under `%LOCALAPPDATA%\Stele\comtypes` and wipe it on version change.

### F12. Supply chain (Medium)

- `requirements.txt`: all `>=`, no hashes, no lockfile. `pytest` and `pyinstaller` are installed into the runtime venv by `run_stele.bat` (SUP-01..03, 06).
- `stele.spec`: `codesign_identity=None`. There is no Authenticode step in `build_stele.py`, no published release digest, and no SBOM of the app itself (SUP-05, SUP-07). `Stele.exe` and the DLLs it bundles are unsigned. The spec also strips `icuuc.dll` and `icudt*.dll` and relies on the OS copy, so watch the DLL search order (§11.4).
- No `.github/workflows`, so no CI test, `pip-audit`, Bandit or Semgrep gate (SUP-04, SUP-08).
- `SECURITY.md` is still the GitHub template, with fake version rows (5.1.x / 4.0.x) and no contact address.

**Fix:**
- split `requirements.in` / `requirements-dev.in`, and generate `requirements.txt` with `pip-compile --generate-hashes`; install with `--require-hashes`
- add a Windows CI workflow: pytest, `pip-audit`, Bandit, and a Semgrep rule pack for `shell=True`, path joins with untrusted names, and `Paragraph(f"…")`
- sign `Stele.exe`, `RESTORE.ps1` and the ZIP, publish SHA-256 with each release, and write a real `SECURITY.md`

### F13. LM Studio runtime pack (Medium)

`stele/runtime/manifest.json` sets `lmstudio`: `url …/download/latest/win32/x64`, `size: null`, `sha256: null`, `version: "0.4.25-1"`. Every download gets whatever "latest" is, with no hash, and the catalog, disc and `SOURCE.txt` call it 0.4.25-1. An executable installer goes onto the archival disc unverified (F5 makes it `done`).

**Fix:** pin the versioned `installers.lmstudio.ai/…/0.4.25-1/…exe` URL with a SHA-256 you measured, or label the pack "unverified, latest" and keep it out of the default burn set. Add `test_every_runtime_pack_has_sha256_and_size`.

### F14. Rich text in labels (Low)

`discover.py:293` (`self.title`) includes the Civitai model `name`. `self.preview` lists file names. `self.notice.setText(str(exc))` shows server error text. All are `QLabel` with `Qt.AutoText`, so text that looks like HTML renders as rich text (images from local paths, misleading formatting). No external links are opened (`setOpenExternalLinks` is unused). The model card itself uses `setPlainText`, which is good. **Fix:** `setTextFormat(Qt.PlainText)` on every label that shows remote text.

### F15. Civitai version fallback (Low)

`civitai.py:134`: `next((v for v in versions if str(v.get("id")) == wanted), versions[0])`. A requested version that was removed silently becomes the newest one. **Fix:** raise `HubError` when `revision` is non-empty and not found.

### F16. Historical HMAC secret (Low now)

`_OFFLINE_SECRET = b"STELE-STUDIO-V1-…"` is in commits `02c6696` and `a06edc0`, and the master list already calls it burned. Builds made before `45b3e8e` still accept keys minted with it. **Action:** make sure no pre-`45b3e8e` build is still offered for download, and never reuse that string. If the repo is or becomes public, consider rewriting history (low value now that the secret is dead).

## 5. Recommended fix order

1. **F1 + F8** (path containment, one shared helper in Python and PowerShell). This closes the only route to code execution found.
2. **F2** (auth only to `huggingface.co`, fail-closed allowlist, strip auth on redirect).
3. **F3** (escape ReportLab input, disable `trustedSchemes`, make finalize transactional).
4. **F4 + F5 + F6** (strict Range handling, size cap, integrity status per file, burn compares against recorded hashes).
5. **F12 + F9** (hash-locked deps, CI with security linters, code-sign exe and script, real `SECURITY.md`).
6. **F10** (signed entitlement) and **F13** (pin LM Studio).
7. **F7, F11, F14, F15, F16** as cleanup.

Each fix should land with the regression tests named above. Together they cover T-001, T-003, T-010, T-012, T-014, T-017 and T-020 from the spec. T-004/T-011 (revision change, missing disc) are already partly covered by `tests/test_split_restore.py`. T-007..T-009 and T-016 wait for an AI feature.
